# Changelog

All notable changes to ON-AIR Meeting Trigger. Format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[SemVer](https://semver.org/). Each version's GitHub release also carries
auto-generated notes and the built `dist.zip`.

## [Unreleased]

### Changed
- Release workflow: the Chrome Web Store upload moves to the store's v2 API
  (v1.1 shuts down 2026-10-15) and checks the store first. If the previous
  version is still in review or approved-but-unpublished, the upload is
  skipped with a warning instead of failing the release, and a new
  **Upload to Chrome Web Store** workflow (Actions → Run workflow) uploads
  a release later. Needs the new `CWS_PUBLISHER_ID` secret.

## [0.8.0] — 2026-10-10

### Added
- Settings: target templates are one-click buttons on the **Add** row —
  **Tasmota**, **Shelly**, **Home Assistant**, **Ntfy push** — next to
  ON-AIR sign, Webhook and Listener (#21, #22).
- Template fill-in parts are marked `YOUR_…`; the card shows
  **⚠ Replace YOUR_…** instead of *Ready*, and Chrome is never asked for
  access to a placeholder host (#21).
- Custom services use the same collapsible card as targets (name · host ·
  status, Remove with Undo); incomplete services are flagged instead of
  silently dropped on save (#20).
- Popup: **Settings** is a full-width button in the same style as Pause (#23).

### Changed
- Webhook bodies starting with `{` or `[` are sent as `application/json`
  unless you set your own `Content-Type` (#21).
- Home Assistant template is a plain webhook POST — no token, no body (#21).
- A custom-service URL typed without `https://` gets it added automatically,
  so it actually matches (#20).
- Form fields in cards always stack title → field → hint (#20).
- Popup: one button style, settings-page font, refreshed status card (#23).
- Docs, README and Chrome Web Store screenshots refreshed for the new UI (#23).

### Removed
- **LED target type** (`simpleLed`, old `/led/on` firmware). Saved LED
  targets are dropped when settings load — use the **ON-AIR sign** target (#21).
- Templates *OnAir IoT* (= the ON-AIR sign button), *On-Air API* (= ON-AIR
  sign, LAN-only) and *Generic JSON* (= Webhook); existing targets made from
  them keep working (#21).

### Fixed
- Adding the same template twice no longer shares settings between the two
  targets (#21).
- Push guide: the Telegram example pointed at Pushover's URL and body (#23).

## [0.7.0] — 2026-10-04

### Changed
- Settings redesign (#19): collapsible target cards with a one-line summary
  (name · host · status) and target names; a one-click **Add** row;
  preferences and detection save instantly, target edits via the save bar,
  which names the sites Chrome will ask to allow; **Test ON / Test OFF**
  results shown inline; Undo after Remove; confirmation before import.
- Popup: health line ("All 3 targets updated 2m ago" / which target failed),
  the detected meeting stays visible while paused, **Pause 1 hour** /
  **Pause indefinitely** / **Resume** / **Extend 1h**; paints instantly from
  a cache.

## [0.6.0] — 2026-10-04

### Security
- Template values are escaped for where they land (URL-encoded in URLs,
  JSON-escaped in JSON bodies), so a crafted meeting link can't inject
  parameters; `{url_raw}` is the explicit unescaped token (#18).
- LAN detection only trusts real private IP literals (`10.evil.com` no longer
  counts as LAN), so the cleartext-token warning can't be bypassed (#18).
- Requests carrying credentials refuse redirects (#18).
- Secrets are detected by pattern (auth/token/key/cookie headers, secret
  query parameters, webhook URLs) and kept out of sync storage; secrets found
  in sync are moved to local storage (#18).
- Host access no longer needed by any target is released; Test buttons run
  through the service worker, which ignores messages from other extensions
  (#18).

### Fixed
- An older ON can no longer arrive after a newer OFF — a new meeting change
  cancels the previous change's in-flight requests (#18).

### Performance
- Config cached in memory; tab events filtered to relevant changes; Chrome
  filters candidate tabs by URL pattern; one permission prompt per save (#18).

## [0.5.1] — 2026-07-02

### Added
- **Verify** for the ON-AIR sign also works away from home, reading the
  state from the cloud bridge when the LAN is unreachable.

### Changed
- Chrome Web Store toolbar tile generated by `make-store-shots.sh`; README
  credits and Ntfy pointers.

## [0.5.0] — 2026-07-01

### Added
- Per-target **reconcile policy** — fire once / verify / re-assert — on a
  1-minute heartbeat.
- Opt-in **diagnostics** log, viewable in a tab or a DevTools panel, with a
  copyable report.

### Fixed
- Duplicate "in a meeting" notifications when Chrome restarted the
  service worker.

## [0.4.4] — 2026-06-22

### Added
- Chrome Web Store screenshot tiles and their generator script.

### Removed
- Duplicate *OnAir Cloud Bridge* template.

## [0.4.3] — 2026-06-21

### Changed
- Theme applies and saves instantly; consistent checkboxes; clearer
  meeting-URL tooltip; empty-state and save-bar polish.

## [0.4.0] – [0.4.2] — 2026-06-21

### Added
- Toolbar popup redesign with big status card and quick **Pause**.
- Unsaved-changes save bar; regrouped settings.
- Choice of whether exports include secrets.
- Dev-build badge for unpacked builds off a non-`main` branch.

### Security
- Tokens and passwords stored in `chrome.storage.local`, never synced.
- `{url}` sends only the meeting site unless full-URL sharing is turned on.
- MV3 reliability: 1-minute alarm heartbeat; persisted state.

### Removed
- Global *Test ALL ON/OFF* buttons and the bottom Save button.

0.4.1 and 0.4.2 were re-releases fixing the manifest version.

## [0.3.1] – [0.3.7] — 2026-05-30

### Added
- **IoT (local + cloud)** target — local HTTP first, AWS IoT cloud-bridge
  fallback, solid or breathing.
- Chrome Web Store draft upload on every release tag.
- Terms of Service.

### Fixed
- Release workflow: re-runs on an existing tag; immutable-release uploads.

## [0.2.0] — 2026-05-30

### Added
- AWS IoT cloud-bridge templates.

## [0.1.0] – [0.1.9] — 2026-01-03 … 2026-01-31

### Added
- Initial release: meeting detection (Meet / Teams / Zoom), listener, LED and
  HTTP-hook targets, Home Assistant guide.
- Custom services; settings export / import.
- Push-notification guide (ntfy, Pushover, Telegram); privacy policy.
- Retry on network / timeout errors (0.1.9).
- Tag-driven GitHub release workflow.

### Fixed
- Dark-theme coverage; settings inputs containing quotes (0.1.9).
